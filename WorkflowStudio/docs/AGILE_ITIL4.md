# Agile & ITIL 4 operating model

## Agile methodologies
The application provides selectable templates and can mix practices by team: Scrum, Kanban, Scrumban, XP, Lean, Crystal, DSDM, FDD, iterative/incremental, hybrid waterfall-agile and SAFe-inspired portfolio coordination. It records which practices are enabled instead of claiming that one framework fits every team.

## ITIL 4 alignment
The service-management module maps service value activities to operational records: plan, improve, engage, design/transition, obtain/build and deliver/support. Core practices represented in the data model include incident, problem, change control, service request, service level, monitoring/event, deployment, release, knowledge, configuration/asset, availability, capacity/performance, information security and continual improvement.

ITIL is a methodology/reference framework, not source code. The application uses its public concepts and terminology carefully and does not reproduce proprietary training materials.

## DevOps flow
Plan → Code → Build → Test → Security → Package → Deploy → Observe → Learn → Improve. Each transition emits auditable events and can be attached to work items and ITIL change records.
